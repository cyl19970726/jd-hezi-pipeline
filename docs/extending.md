# 扩展指南

## 新增类目

1. 在真实目标平台打开该类目的规格参数页。
2. 使用 `template-read` 或受控导入保存模板及观察时间。
3. 准备一个事实完整、授权明确的样本 SKU。
4. 为字段归一化、必填判断、表单填写和读回补测试。
5. 先写草稿，独立读回，再小批提交。
6. 把页面版本、失败样本和人工介入记录下来。

```sh
node dist/cli.js --dir "$HEZI_DIR" template-read '<category-id>'
```

## 新增页面适配

页面适配应放在 `src/browser/`，并遵守：

- 先验证当前 URL、登录状态、店铺身份和页面结构。
- 使用有界等待和唯一语义选择器，不使用无限重试。
- 识别错误页、权限页、风控页和加载空壳。
- 每次外部写入前返回可持久化意图所需信息。
- 写入后另走读回逻辑，不复用“刚填过所以应该保存了”的假设。
- 为真实 DOM 样本建立合成 fixture 或最小回归测试。

## 新增分析数据

分析模块只能在 `src/analytics/` 中读取本地事实或新的观察数据。新增指标时至少定义：

- 数据粒度：商品、SKU、店铺还是日。
- 时间范围和缺失规则。
- 金额、销量、曝光、评价或搜索指数分别代表什么。
- 是否存在幸存者偏差、重复 SKU 或口径不可比。
- 何时可以触发 handoff，何时只能作为研究线索。

分析指标不能直接改写运营状态，也不能把预测当成已发生订单。

## Prompt / 文本模型边界

文本模型只在输入输出可校验的窄任务中使用，例如受控标题改写或字段歧义分类。任何模型结果都必须：

- 带来源或允许规则；
- 在程序侧验证；
- 不创建价格、授权、身份或发布状态；
- 在失败时回到 NEEDS_INPUT。

如果确定性规则足够，优先不调用模型。

## 发布前检查

```sh
npm run build
npm test
npm run demo
node scripts/check-repository-policy.mjs
npm run format:check
```

涉及外部写入的改动还要在隔离测试店铺或草稿阶段验证。自动测试通过不能代替真实验收。
